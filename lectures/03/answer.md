# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：講座固有の情報を今回は含んでいたので、読み取りがしやすくなった。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」と質問したところ、search_glossary が2回呼び出された。引数は、それぞれ {'query': 'LoRA'} と {'query': 'QLoRA'} だった。各ツールから用語の定義と関連する講義回が返され、その情報を使って最終回答が生成された。

実行ログは requests=2、tool_calls=2 だった。モデルは1回目の呼び出しで2つの検索を依頼し、2回目で検索結果をもとに回答を作成した。この結果から、ツールを使う指示はモデルが出し、実際の検索はプログラムが実行する流れを確認できた。
- 1つの質問での LLM 呼び出し回数（`requests`）：２回
- 追加したツールと、docstring に書いた説明：
指定した講義回の用語から確認問題を作る make_quiz(lecture: int) -> str を追加した。load_glossary() で用語集を読み込み、lecture が指定された回と一致する用語を集め、random.choice() で1つ選ぶ。その用語名を使った問題と、definition を使った答えを、JSON形式の文字列で返す。指定した回の用語がない場合は、問題を作れない旨を返すようにした。

docstringには、「指定した回の用語から1つ選び確認問題と答えを返す」「『第3回の確認問題を出して』のように、回の内容を復習したいときに使う」と記載した。これにより、モデルにツールの役割と使用する場面を伝えた。また、app/agent.py に agent.tool_plain(tools.make_quiz) を追加し、エージェントが利用できるツールとして登録した。

## 宿題

- 取り組んだレベル：実装
- やったこと：学習テーマと学習内容を受け取り、learning_log フォルダにJSONファイルとして保存する save_learning_log ツールを作成した。

登録時に requires_approval=True を指定し、モデルが保存を依頼すると、DeferredToolRequests を返して実行前に停止するようにした。その後、CLIでツール名と引数を表示し、利用者が入力した承認・拒否の結果を DeferredToolResults に入れて、会話履歴とともに渡して処理を再開する仕組みを追加した。
- 結果：ツール一覧に save_learning_log が表示され、引数として topic と content が登録されていることを確認した。

保存を依頼すると承認画面が表示され、n を入力した場合には「拒否しました」と表示された。y を入力して承認した場合には、learning_log フォルダにJSONファイルが1個作成された。また、変更後に uv run pytest -q を実行し、テストが通ることを確認した。



- 気づき・疑問：ツールを作成・登録することと、モデルが実際にそのツールを呼び出すことは別だとわかった。ツール一覧への表示だけでなく、実行ログや作成されたファイルまで確認する必要がある。また、「保存前に確認する」とモデルに指示するだけでなく、プログラム側でツールの実行を止め、利用者の入力を受け取る仕組みを設けることが重要だとわかった。今回の実装を通して、モデルが操作を依頼し、周辺プログラムが承認確認や実行を管理する役割分担を理解できた。
